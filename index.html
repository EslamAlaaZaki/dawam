How it works

From source systems to an approved warehouse

DAWAM follows the stages of a warehouse project. Every change, from a person, the AI or a schema sync, arrives as a reviewable Change Set.

Connect

Live connections or a schema file, kept as versioned Snapshots.

Documents

Upload SDAs, specs and ERD images; DAWAM indexes them.

Understand

ER diagrams, profiles, PII scans and inferred relationships.

KPIs

A KPI catalog linked to real source columns.

Design

Generated staging, Core and Mart, validated mappings with lineage.

Evaluate

Quality score, approval gate, then DDL and documentation.

Why teams use it

One place instead of scattered drawings and spreadsheets

Understand undocumented sources

Profile data, find undeclared relationships and let the AI draft descriptions and a gaps report.

Find personal data early

Arabic and English PII rules on names and sampled values, followed through lineage into the warehouse.

Answer "where does this number come from?"

Column-level lineage from any KPI or warehouse column back to its source columns.

Design a Kimball warehouse

Staging generated automatically; Core and Mart with grain, SCD types and validated mappings.

Absorb schema changes safely

Re-sync a source, see every affected asset, accept the propagated fixes in full or in part.

Run anywhere, even air-gapped

Self-hosted with Docker Compose; use local models (Ollama, vLLM, SGLang) so nothing leaves your network.

AI assistant

✦ An agent that works on real data

  • Explores sources through tools that read the real schema, statistics and data, not guesses.
  • Searches your uploaded documents (full-text and vector search) and cites the passages.
  • Acts with the user's permissions; everything it changes arrives as a Change Set to review.
  • Runs on any model: OpenAI-compatible servers, Anthropic, Azure OpenAI, Gemini or AWS Bedrock.
